# Solver v2 — plano de implementação

> **Para agentes:** execute por superpowers:subagent-driven-development, uma tarefa por vez.
> Cada tarefa diz quem a implementa: **agy** (Antigravity CLI, `gemini-4-argon-high`, contrato
> fechado, não roda git) ou **subagente Claude** (algoritmo, decide detalhes). O controlador
> (Claude) revisa, roda as verificações e faz os commits.

**Objetivo:** um solver v2 ao lado do v1 que bate a meta do spec (0 faltantes ou o mínimo no
cenário de 3 salas, custo abaixo da linha de base, 0 violações, ~2 s, determinístico), rodando
num Web Worker com progresso e botão de parar.

**Spec:** `docs/superpowers/specs/2026-11-06-solver-v2-design.md` (leia antes de qualquer tarefa).

**Stack:** Tauri v2, React 19 + TS 5.8, Vite, Vitest (ambiente node), Playwright.

## Restrições globais

- Textos de interface, comentários e mensagens de commit em **português do Brasil**. Comentário
  explica o *porquê*, no estilo do código vizinho. Nada depende de nome próprio.
- **O v1 não muda:** `src/solver/solver.ts` fica intacto (exceto o que a Task 3 pede para
  rodá-lo no Worker, que é só importá-lo). `src/regras/` não muda.
- **Os pesos não mudam:** `PESOS_PADRAO` e `custo.ts` ficam como estão. O custo do v2 é medido
  pela mesma `custoTotal` do v1.
- **Determinismo:** um único `aleatorio(opcoes.semente ?? 12345)` criado no início do `resolver`
  do v2 é a única fonte de sorteio. Nunca `Math.random()` nem relógio na decisão.
- **Invariantes do v1 que o v2 mantém:** fixadas e externas nunca saem de `estado.oc`; desconto
  das fixadas (`fixasPorFatia`) e `diasProibidos` como estão; o `try … finally { passos = antesDosPassos }`
  da Fase 2 (B7).
- Toda tarefa termina com `npm run typecheck` e `npm test` verdes. Tarefas que mexem em tela
  terminam também com `npm run test:e2e` verde.
- **Benchmark:** toda tarefa que mexe no algoritmo do v2 termina com `npm run bench:solver` e
  acrescenta a tabela do v2 (e o resumo: custo médio por cenário, faltantes, ms) a
  `testes/benchmark/v2-progresso.md`, sob um título `## Task N — <nome>`. Uma tarefa pode piorar
  o custo (a nota marginal sozinha pode); isso se registra, não se esconde.
- Commits com o trailer do modelo que de fato escreveu: `Co-Authored-By: Gemini 4 Argon <noreply@google.com>`
  nas tarefas do agy, `Co-Authored-By: Claude <modelo> <noreply@anthropic.com>` nas do Claude.
  Sem `git push`.

### Task 2: Execução em passos — **subagente Claude (sonnet)**

**Arquivos:** `src/solver/v2/solver.ts`, `src/solver/tipos.ts`, criar `src/solver/v2/passos.test.ts`.

**Interfaces (exatas, ver spec "Execução em passos"):**

```ts
export interface Progresso { fase: "construcao" | "melhoria"; rodada: number; rodadas: number; melhorCusto: number; }
export type Comando = "parar" | undefined;
export function resolverEmPassos(problema: Problema, opcoes?: Opcoes): Generator<Progresso, Resultado, Comando>;
export function resolver(problema: Problema, opcoes?: Opcoes): Resultado; // esgota resolverEmPassos
```

- Em `tipos.ts`, `Resultado` ganha `interrompido?: boolean` com comentário ("parado pelo usuário
  antes do fim das rodadas; a grade é a melhor vista até ali").
- Cede ao fim da construção (`fase: "construcao", rodada: 0`) e depois de cada múltiplo de 100
  rodadas de melhoria (`fase: "melhoria"`). Recebendo `"parar"`, sai do laço e devolve o
  resultado com `interrompido: true`. `milissegundos` continua sendo o tempo total.
- `resolver` não muda de comportamento: mesma grade, custo e passos que antes desta tarefa.

**Testes (`passos.test.ts`, massa via `carregarProblema(1, lerDe(criarBanco()))`):**
1. Esgotar `resolverEmPassos` dá o mesmo `alocacoes`, `custo` e `passos` que `resolver` (semente 7, 300 rodadas).
2. A sequência de progresso começa com `construcao` e as rodadas de `melhoria` crescem de 100 em 100.
3. Mandar `"parar"` no primeiro progresso de melhoria devolve `interrompido: true`, `conferir(p, r.alocacoes)` vazio e `r.custo` igual a `custoTotal` das alocações.

**Pronto quando:** typecheck e testes passam; o benchmark do v2 continua idêntico ao do v1

### Task 5: Custo incremental — **agy**

**Arquivos:** criar `src/solver/v2/custoIncremental.ts` e `src/solver/v2/custoIncremental.test.ts`;
modificar `src/solver/v2/solver.ts` (só a Fase 2).

**Contrato:**

```ts
export class CustoIncremental {
  constructor(problema: Problema, pesos: Pesos, iniciais: Alocacao[]);
  adicionar(aulas: Alocacao[]): void;
  remover(aulas: Alocacao[]): void;   // remove por igualdade de todos os campos
  total(): number;                    // === custoTotal(problema, <conjunto atual>, pesos), sempre
}
```

Mantém, por chave, o estado que cada termo de `src/solver/custo.ts` precisa (horas por
professor+dia e por período+dia de obrigatórias; contagem fora do turno; disciplinas fora do turno
por período; aulas por optativa; dias por professor; aulas em sala aceitável) e recalcula **só as
chaves tocadas**. Leia `custo.ts` inteiro: cada termo tem de dar exatamente o mesmo número.

**Teste obrigatório (copie como está):**

```ts
import { describe, expect, it } from "vitest";
import { criarBanco, lerDe } from "../../../testes/suporte/banco";
import { carregarProblema } from "../carregar";
import { custoTotal } from "../custo";
import { resolver } from "../solver";
import { PESOS_PADRAO, type Alocacao } from "../tipos";
import { CustoIncremental } from "./custoIncremental";

describe("CustoIncremental", () => {
  it("acompanha custoTotal em 2000 remoções e adições sorteadas", async () => {
    const p = await carregarProblema(1, lerDe(criarBanco()));
    const grade = resolver(p, { rodadasDeMelhoria: 0 }).alocacoes;
    let s = 99;
    const sorteio = () => ((s = (s * 1664525 + 1013904223) >>> 0) / 4294967296);
    const dentro: Alocacao[] = [...grade];
    const fora: Alocacao[] = [];
    const c = new CustoIncremental(p, PESOS_PADRAO, dentro);
    expect(c.total()).toBe(custoTotal(p, dentro, PESOS_PADRAO));
    for (let i = 0; i < 2000; i++) {
      const tirar = fora.length === 0 || (dentro.length > 0 && sorteio() < 0.5);
      const [de, para] = tirar ? [dentro, fora] : [fora, dentro];
      const k = Math.floor(sorteio() * de.length);
      const [a] = de.splice(k, 1);
      // Hora e dia mexidos para cair em chaves diferentes das originais.
      const movida = tirar ? a : { ...a, dia: Math.floor(sorteio() * 5), hora: a.hora };
      para.push(movida);
      if (tirar) c.remover([a]);
      else c.adicionar([movida]);
      expect(c.total()).toBe(custoTotal(p, dentro, PESOS_PADRAO));
    }
  });
});
```

**Integração:** na Fase 2 do v2, o `custoTotal(problema, materializar(...), pesos)` de cada rodada
é trocado pelo `CustoIncremental`: ao retirar uma fatia, `remover` as aulas dela; ao recolocar,
`adicionar`; ao desfazer, o inverso. O resultado final continua calculado por `custoTotal` (é a
régua). Grade, custo e passos do v2 têm de ser **idênticos** aos de antes desta tarefa para a
mesma semente; só `milissegundos` muda.

**Pronto quando:** typecheck e testes passam; benchmark registrado, com o tempo comparado ao da Task 4.

### Task 6: Fase 2 com Top-K, LAHC e faltantes — **subagente Claude (sonnet)**

**Arquivos:** `src/solver/v2/solver.ts`, criar `src/solver/v2/melhoria.test.ts`.

- `colocarBlocos`/`colocarFatia` ganham `amostragemTopK` (1 na Fase 1) e `evitar?: Bloco[]`: com
  K > 1, sorteia (pelo `sorteio` único) entre os `min(K, n)` melhores candidatos, mandando a
  posição igual a `evitar` para o fim. Na Fase 2, K = 5 e `evitar` = blocos anteriores.
- Aceitação LAHC: histórico de `L = max(50, min(250, floor(rodadas / 8)))` custos, iniciado com o
  custo pós-Fase 1. Aceita se `agora <= custoAtual || agora <= historico[r % L]`; ao fim da
  rodada, se `custoAtual < historico[r % L]`, grava. Guarda `melhorCusto` e uma cópia dos
  `colocados` da melhor grade; ao fim (e ao parar), restaura a melhor.
- Faltantes: a cada rodada, com chance 0,1 e se houver faltante, a rodada tenta colocar uma
  faltante em vez de mexer numa colocada; conseguindo, ela sai de `faltantes` e entra em `colocadas`.
- 600 rodadas sem melhorar `melhorCusto`: restaura a melhor e segue.

**Testes:** determinismo com LAHC (mesma semente, mesma grade); `r.custo` nunca maior que o custo
pós-Fase 1 (rodadas 0 vs. 2000); grade sempre aprovada pelo `conferir`.

**Pronto quando:** typecheck, testes e benchmark registrado. Espera-se queda de custo na massa real.
